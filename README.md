# gin-tonic

`gin-tonic` is a Rust protobuf library that lets you use your own types directly on the wire — no manual conversion boilerplate.

It provides:

- Protobuf serialization and deserialization (like [`prost`](https://docs.rs/prost))
- A code generator replacing [`prost-build`](https://docs.rs/prost-build)
- A [`tonic`](https://docs.rs/tonic) codec implementation
- A wrapper for [`tonic-build`](https://docs.rs/tonic-build) with extra features
- A `Scalar` trait to map any Rust type directly to a protobuf wire type

## The problem with other libraries

When you use a UUID in a protobuf message with `prost`, you write:

```protobuf
message Foo {
  string my_uuid = 1;
}
```

This generates:

```rust
struct Foo {
    my_uuid: String,
}
```

Your code wants `uuid::Uuid`, so you end up writing conversions everywhere — and handling parse errors at every call site.

## The gin-tonic approach

Annotate your `.proto` file with the Rust type you want:

```protobuf
import "gin/proto/gin.proto";

message Foo {
  string my_uuid = 1 [(gin_tonic.v1.rust_type) = "uuid::Uuid"];
}
```

The `gin-tonic` code generator produces:

```rust
struct Foo {
    my_uuid: uuid::Uuid,
}
```

The conversion is handled once, inside the `Scalar` trait implementation — not scattered across your codebase.

## Built-in UUID support

Two feature flags cover the UUID case out of the box:

| Feature | Wire type | Notes |
|---|---|---|
| `uuid_string` | `string` | Parse errors handled in the wire type conversion |
| `uuid_bytes` | `bytes` | No parse errors; 16-byte fixed representation |

## Custom types

Implement `Scalar` for any type to use it as a protobuf field:

```rust
impl gin_tonic_core::Scalar<gin_tonic_core::scalars::ProtoString> for MyType {
    const WIRE_TYPE: u8 = gin_tonic_core::WIRE_TYPE_LENGTH_ENCODED;

    fn encode(&self, encoder: &mut impl gin_tonic_core::Encode) {
        encoder.encode_str(&self.to_string());
    }

    fn decode(decoder: &mut impl gin_tonic_core::Decode) -> Result<Self, gin_tonic_core::ProtoError> {
        decoder.decode_string()?.parse().map_err(Into::into)
    }
}
```

## Validation

Import `buf/validate/validate.proto` (protovalidate, provided on the include path by the consumer) and annotate fields with `(buf.validate.field)`:

```protobuf
import "buf/validate/validate.proto";

message Ta {
  int32 period = 1 [(buf.validate.field).int32 = {gte: 1, lte: 10000}];
}
```

The generator translates the rules into `#[gin(validate(...))]` attributes, and the `Message` and `OneOf` derives implement `gin_tonic::Validate` for every message and oneof enum. Supported rules:

| Field type | Rules |
|---|---|
| integers (`int32`, `int64`, `uint32`, `uint64`, `sint*`, `fixed*`, `sfixed*`) | `gt`, `gte`, `lt`, `lte` |
| `double`, `float` | `finite`, `gt`, `gte`, `lt`, `lte` |
| `string` | `min_len`, `max_len` (Unicode code points), `uuid` |
| `repeated` | `min_items`, `max_items`, `unique` (scalars and strings), `items` with the rules above |
| `map` | `min_pairs`, `max_pairs`, `keys` and `values` with the rules above |

Bounds follow protovalidate, including inverted ranges and NaN failing every bound. Any other field rule (`cel`, `required`, `ignore`, `const`, `in`, `pattern`, `email`, bytes/enum/bool/well-known type rules, predefined extensions, rules on `rust_type` fields), as well as `(buf.validate.message)` and `(buf.validate.oneof)`, fails code generation with an error naming the field and rule.

`validate()` recurses into nested message values (singular, optional, repeated items, map values and oneof variants) of generated types and `extern_path` types (generated by gin-tonic as well), but not into custom `rust_type`s or the well-known types mapped to Rust primitives. Hand-written `#[derive(Message)]` types validate nothing unless annotated with `#[gin(validate(...))]`; hand-written `Message` impls used with `GinCodec` must implement `Validate`.

`GinCodec` validates every decoded message (requests on servers, responses on clients) and returns `INVALID_ARGUMENT` with a message such as ``field `rule.ta.period` must be <= 10000``. `ValidationError` exposes the path, whether a map key is affected, and the typed `Violation`. Encoding is not validated.

## Benchmarks

Measured against prost 0.14.3 on an equivalent message with a UUID, 10 IP addresses, a string, and a nested map with 5 entries on AMD Ryzen AI 7 350.

**gin-tonic:**
```
gin_encode    time:   [1.0944 µs 1.0957 µs 1.0974 µs]
gin_decode    time:   [2.4878 µs 2.4886 µs 2.4893 µs]
```

**prost** (including `From` conversions to idiomatic Rust types):
```
prost_encode  time:   [2.3426 µs 2.3477 µs 2.3568 µs]
prost_decode  time:   [2.7674 µs 2.7731 µs 2.7772 µs]
```

Decode performance is slightly better while encoding is about twice as fast.
